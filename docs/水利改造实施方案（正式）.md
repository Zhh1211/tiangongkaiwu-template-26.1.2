## 1. 分批施工

### 批 1 · 动力网地基（纯改造，无新玩法方块）

> **✅ 代码框架已铺（2026-09-30）**：PowerNetwork（无 BE 确定性 BFS 分配）/ GearBlock 牙轮 /
> ShaftBlock（轴向传播+自动成型+零损耗，模型重做为真杆+三向变体）/ 碓接分配（定额 3）。
> 牙轮配方：6 木板+1 木棍（有序）。**编译验证待用户跑**（沙箱拦了 gradle）。
> 附加发现：旧杆模型只是中央 6³ 方墩且块状态无 axis 变体——已一并重做为真梁三向。
> 旧档兼容：杆/碓无状态表变更（POWER 语义改为网络劲总量，仅贴图），安全。

| 项 | 内容 | 参照 |
|---|---|---|
| 1a | 传动杆改**轴向传播**（同轴邻格 max）+ 放置/邻变自动成型（AXIS 跟随邻轴） | D3，Create shaft 行为 |
| 1b | 新方块**牙轮**：AXIS 属性；连接垂直邻轴、不直通；模型带齿 | D4 |
| 1c | **劲网络**（新类 `PowerNetwork`）：sources/members 两表 + Σ求和 + 脏标记低频重建 + 卸载记账；改写自 KineticNetwork（181 行） | D6，MIT |
| 1d | 碓接新网络：定额 3 劲；**劲不足 → 出糙米**（替换现行"邻轴 power≥3"判定）；Jade 提示改读分配结果 | D6 |

**验收**：① 两排紧贴的产线互不串劲（轴向传播）；② 横轴尽头放牙轮接竖轴，碓照转；③ 一台踏车带 2 台碓
→ 全部"不及"出糙米（5 < 3+3）；带 1 台 → 出米；④ 拆一段轴，网络分裂各自结算；⑤ 旧档碓/轴无异常。

### 批 2 · 流体梘网（本计划的核心批次）

| 项 | 内容 | 参照 |
|---|---|---|
| 2a | 梘重做：**BE + 8 级水位**；去 FACING 自动邻接；六面模型按邻接成型；水位渲染（板层高度） | D7/D11 |
| 2b | **转移结算**：每 10 tick，水位差 ≥1 流 1 级；**先 SIMULATE 后 EXECUTE 两轮**；低频 + WeakReference 缓存 | §10.7.3 |
| 2c | 新方块**筒**：吃劲（邻轴/贴车），邻向抽水（只抽 source）、六向注入含上方；**注水间隔 = 48/劲 tick**（12→4s、10→4.8s、5→9.6s、2→24s） | D8/§8.5 |
| 2d | 灌田：有水位（≥1）的梘段给侧向稻田补水，**+1 田水耗 1 级水位**；枯秆可救活 | D7 |
| 2e | **capability**：梘段与筒暴露 `IFluidHandler`（读水位/注入/抽取）；桶互动暂不做 | D9 |
| 2f | 旧档迁移：旧梘（抽象 watered 布尔）自愈为 BE 水位 8；Jade 显示"水位 N/8" | D11 |

**验收**：① 平地铺 10 格梘，源头注入 → 近满远浅的梯度可见；② 远田灌得慢，中途加筒后恢复；
③ 竖着叠梘不通水，放筒才上去；④ 抽水只抽 source（流动水不消失）；⑤ 旧档梘自动迁移。

## 2. 风险与纪律

1. **每批必须进游戏验收**（教训：StreamCodec 空值编译期查不出，单人直接进不去世界）。
2. **capability 是红线**：梘/筒的流体接口从批 2 起就要按"将来跑卤水/油"的标准写，不做水专用 hack。
3. **性能**：劲网络与水位结算全部低频（≥10 tick）+ 脏标记；几十台规模实机测过才算数（4GB 机器）。
4. **旧档**：批 1（轴/碓）不改状态表，安全；批 2/3 动梘与装置，必须有自愈路径，否则提示重建。
5. **每批一个提交序列**，做完跑 `audit_book_spec.py`/`audit_resources.py` + 手动 javac / gradle 离线编译，
   更新测试清单，再交用户验收。

## 3. 批间依赖

```
批1 动力网 ──► 批2 梘网（筒要吃劲）──► 批3 堰+BER（BER 要批2 的 BE）──► 批4 排涝 ──► 批5 收尾
```

批 1 与批 2 之间无回退依赖：若批 2 中途叫停，批 1 成果（轴向传播/牙轮/劲）独立成立。

## 4. 批 1 开工前需要用户点头的事项

1. 本方案整体批准（或指出要改的条目）；
2. 碓的劲定额 = 3（一台踏车 5 恰好带 1 台透、两台都"不及"）——认不认这个刻度；
3. 批 1 完成后是否先实机验一批再继续（建议是）。
