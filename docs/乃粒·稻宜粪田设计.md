# 乃粒 · 稻宜（粪田养地）玩法设计

> 依据：《天工開物·乃粒·稻宜》（原文存档 `docs/天工开物·乃粒原文.md`）
> 状态：设计草案（待拍板），尚未实现。关联：细糠（碓副产物）→ 养猪 → 粪肥（设计文档 §3.6）

## 1. 原文照录

> 凡稻，土脈焦枯則穗、實蕭索。勤農糞田，多方以助之。人畜穢遺，榨油枯餅（枯者，以去膏而得名也。胡麻、萊菔子為上，蕓薹次之，大眼桐又次之，樟、桕、棉花又次之），草皮木葉，以佐生機，普天之所同也（南方磨綠豆粉者，取溲漿灌田肥甚。豆賤之時，撒黃豆于田，一粒爛土方寸，得谷之息倍焉）。土性帶冷漿者，宜骨灰蘸秧根（凡禽獸骨），石灰淹苗足，向陽暖土不宜也。土脈堅緊者，宜耕壟，疊塊壓薪而燒之，填墳鬆土不宜也。

## 2. 书里的结构（这是最值钱的部分）

它**不是**"施肥 → 变好"这么含糊，而是分成两层：

### 2.1 肥料有来源、有等级

| 书里的原文 | 来源 | 备注 |
|---|---|---|
| 人畜穢遺 | 人畜粪 | 最普适 |
| **榨油枯餅** | 榨油后的饼粕 | **书里明确排了序**：胡麻 > 萊菔子 > 蕓薹 > 大眼桐 > 樟/桕/棉花 |
| 草皮木葉 | 草皮、树叶 | 堆肥，随处可得 |
| 溲漿（南方磨绿豆粉者） | 绿豆浆水 | "肥甚"——效果最好的一档（原注） |
| 撒黃豆于田 | 黄豆 | "一粒爛土方寸，得谷之息倍焉"——**与「菽」条目天然联动** |

### 2.2 土性不同，改土法子不同（关键：用错无效）

| 土性（书） | 改土法（书） | 反向警告（书） |
|---|---|---|
| 土性帶**冷漿** | **骨灰**蘸秧根（凡禽兽骨）、**石灰**淹苗足 | "向陽暖土不宜也" |
| 土脈**堅緊** | **耕壟，疊塊壓薪而燒之**（烧土） | "填墳鬆土不宜也" |
| 土脈**焦枯**（一般瘦田） | 粪肥 / 枯餅 / 草皮木葉 | — |

## 3. 落到游戏里

### 3.1 土性怎么认（复用 A 批已有的底材）

A 批（水利）已经规定"底材定保水天数"。这次补上**土性**这一维，用同一张底材表：

| 底材 | 土性（书） | 对症的改土法 | 用错的后果 |
|---|---|---|---|
| 沙子、砂砾、粗泥 | **堅緊**（硬结、瘠薄） | 烧土（堆柴烧田） | 骨灰/石灰无效 |
| 黏土、黏土块 / 常年积水的田 | **冷漿**（湿冷、地温低） | 骨灰（+石灰） | 烧土无效 |
| 泥土、泥巴、草方块 | 普通瘦田 | 粪肥 / 堆肥 | — |

### 3.2 v1（轻量版，建议先做这个）

**不引入新方块、不引入地力数值**，只做"道具对特定土性生效"——完全贴书、可当场验证：

- 新物品 **粪肥** `fen_fei`：`useOn` 稻田 → 立刻催熟一大截（比骨粉强，且可连续用）
- 新物品 **骨灰** `gu_hui`（烧骨头得）：只对**冷浆土**上的稻有效；对沙/砂砾无效（书：向陽暖土不宜）
- **石灰** `shi_hui`：同上，冷浆土专用第二档（可后置）
- **烧土**：对**坚紧土**有效——做法是"在田上堆薪烧之"：手持柴（原版 `#minecraft:logs`/木棍）右键坚紧土 → 消耗并"烧"一次（冒烟 + 提升），对松土无效
- **骨粉弱化**（原设计文档里的待办）：骨粉对稻只做微效（例如只能推进 1 个生长阶段），逼玩家用对症的肥

### 3.3 v2（地力数值 + 熟田方块，后置）

- 新方块 **熟田** `shu_tian`（泥土质，`fertility` 0–7）：施粪 +1~2，收获 −1；地力直接乘到**产量**上（书"土脈焦枯則穗、實蕭索"就是减产）
- 枯餅体系：将来做「油坊」（麻/菔/芸薹榨油）后，饼粕按书里的**等级表**给不同肥力——这也是「麻」条目的加工线
- 溲漿（绿豆浆）与"撒黄豆"两条留给「菽」条目联动

### 3.4 细糠接哪里

碓 → `rice_bran` 细糠（书：**以供犬豕之豢**）→ **喂猪** → 猪产 **粪肥**。
这样"种稻 → 舂米 → 糠喂猪 → 猪粪肥田 → 稻更好"闭环，和书里那条"人畜穢遺"完全对上。

## 4. 待拍板

1. **本批范围**：v1 轻量版（道具对土性生效）／ 直接上 v2（地力 + 熟田方块）／ 只做"细糠→猪→粪肥"这一环先试水。
2. **粪肥从哪来**：细糠喂猪（贴书、闭环，但要喂猪机制）／堆肥（草+树叶+水，简单）／两者都要。
3. **稻的生长/产量是否现在就与肥力挂钩**：现在只做"催熟"（不动现有生长逻辑，安全）／同时改产量（改动大，需重跑收穗回归）。

## 5. 风险

- 动 `rice_stalk`（加属性）会**再次改动方块状态表**，旧档稻田可能错乱——v1 不碰它，这是推荐 v1 的主因。
- 产量公式一改，"能种能收能合成"的老验收要重跑。
